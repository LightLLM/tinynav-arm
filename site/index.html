Open research prototype

One brain for every robot body.

Drones, humanoids, arms and legged robots are usually run by separate AI models. This project tests whether a single model, with one set of weights, can control all of them by taking the robot's body as an input.

View the code See the results

Where it stands: the architecture runs on four robot models in simulation and passes its tests. The learned policies do not yet complete any task on those robots. The numbers below include that failure.

The body is an input, not an assumption

Every joint or rotor becomes a token that carries its own physical description. The network has no layer whose shape depends on the robot, so a 29-joint humanoid and a 4-rotor drone pass through the same weights.

Describe

Per-joint tokens

Joint type, axis, limits, actuator strength and position in the body are read straight from the robot model.

Share

One trunk

A transformer with an action head and a head that predicts the robot's next state. Only one small vector per body is robot-specific.

Guard

Reflex layer

A deterministic filter between the model and the motors that clamps commands and stops on a fall. A demonstration, not certified safety software.

How a command is produced

Sensors as tokensJoint positions and velocities, body orientation and motion. Cameras, sound, touch and language are designed for but not built yet.
↓
Body descriptionOne description per joint or rotor, plus a learned prompt per robot.
↓
Shared trunk: the same weights on every robotAbout 920,000 parameters in this prototype.
↓
Action chunkEight control steps per joint, generated by flow matching.
↓
Outside the brainReflex layer, then the robot's own low-level controllers.

What comes next

  1. Find out why the learned policies fail: check whether the model reproduces the teacher's actions on recorded data, then test more training, a larger model and recovery-rich demonstrations.
  2. Replace the scripted teachers with controllers trained by reinforcement learning, so tasks can include walking and reaching.
  3. Add a camera and a language instruction through a pretrained vision-language-action model.
  4. Rerun the specialist-versus-shared comparison across more seeds once any policy succeeds.
  5. Only then move to hardware, starting with a low-cost arm.

Run it yourself

Python 3.10 or newer. No GPU or robot needed.

git clone https://github.com/LightLLM/tinynav-arm
cd tinynav-arm
pip install -e '.[dev,ueb]'
git clone --depth 1 https://github.com/google-deepmind/mujoco_menagerie third_party/mujoco_menagerie

pytest -q                      # 19 tests
python tools/ueb_fleet.py      # four robots, about 45 minutes on 4 CPU cores
